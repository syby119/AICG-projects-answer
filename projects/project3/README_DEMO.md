# Project 3：CAD 智能体

本课程设计规定使用 **GLM-5.3-Flash** 与 SimpleCADAPI（SCA）完成交互式参数化建模，展示需求理解、工具调用、模型生成、几何检查和反馈修正的过程。

OpenCode 负责对话上下文和 Agent 工具调用循环，SCA 官方 Skill 提供建模流程与 API 使用规范，SCA 原生编辑器展示代码和三维模型。Agent 根据任务自主选择查阅资料、提问、编写代码、执行和修复操作。

本 demo 使用 OpenCode 作为 harness 演示，也可以采用支持 Skill 和多轮工具调用的其它框架。

## 1. 学习目标与先修知识

1. 将自然语言需求整理为结构、尺寸、单位和位置关系。
2. 理解 harness、Skill、模型与工具之间的分工。
3. 使用 SCA 编写和修改参数化模型。
4. 对实际几何进行检查，并利用执行反馈修正模型。
5. 在多轮修改中保留未改变的要求，导出可复现的源文件和几何文件。

先修知识包括 Python 基础、三维坐标、基本实体、布尔运算和参数化建模。

## 2. 环境配置与运行

| 组件 | 用途 |
| --- | --- |
| Python 3.12 / uv | 管理项目环境与依赖 |
| Node.js / npm | 安装 OpenCode |
| OpenCode 2.0.20 | 提供对话、上下文与工具执行循环 |
| SCA 2.2.6.post2 与官方 Skill | 提供几何能力、建模规范和编辑器 |
| GLM-5.3-Flash API | 课程规定使用的模型，负责需求理解、推理与工具调用 |

在 `projects/project3/` 下安装：

```bash
uv sync --python 3.12
uv run python demo.py install
```

复制 `.env.example` 为 `.env`，填写 `LLM_BASE_URL`、`LLM_MODEL` 和 `LLM_API_KEY`。然后在两个终端分别运行：

```bash
uv run python demo.py editor
```

```bash
uv run python demo.py agent
```

浏览器打开 <http://127.0.0.1:8765> 查看模型，在 OpenCode 终端中输入建模需求。软件安装、配置和故障排查见 [SETUP_GUIDE.md](SETUP_GUIDE.md)。

## 5. 建模流程与数据约定

### 5.1 Agent 建模流程

![CAD Agent 建模流程：用户输入需求，加载 Skill，按需澄清，编写代码，执行并检查，失败后修复，通过后导出](docs/images/modeling-flow.svg)

1. **输入需求：** 用户描述零件结构、尺寸、单位和位置关系。
2. **加载知识：** Agent 加载官方 Skill，选择对应工作流并查阅相关 API。
3. **判断下一步：** 条件不明确时提问，收到回答后继续；条件足够时进入建模。
4. **编写代码：** 创建或修改参数化 notebook，保留未修改的要求。
5. **执行模型：** 通过 SCA 执行代码并读取输出；发生错误时回到代码修改。
6. **检查结果：** 在编辑器中查看模型，测量实际尺寸与结构；不符合要求时继续修正。
7. **导出交付：** 保存参数化源文件、所需几何格式及检查记录。

图中展示主要反馈关系。具体工具及调用次数由 Agent 根据上下文和反馈选择。打开编辑器协作时，Agent 使用 `sca snapshot` 读取状态，并按 Skill 指引使用 `sca cell` 修改当前 notebook。

### 5.2 坐标、单位与参数

| 项目 | 约定 |
| --- | --- |
| 长度单位 | 使用 mm，其他单位先换算 |
| 世界坐标 | 采用右手坐标系，明确基准平面和轴向 |
| 位置关系 | 区分孔中心距、孔边距及基准面距离 |
| 缺失条件 | 对影响建模的关键歧义向用户提问 |
| 多轮修改 | 只修改指定参数，保留其他要求 |

例如“孔距边缘 10 mm”需要明确是孔中心到板边的距离，还是孔边到板边的距离。

### 5.3 建模记录

保留需求、命名参数、notebook、工具反馈、几何测量和导出文件。测量值应来自实际几何，而不是直接复制输入参数。包围盒可以检查整体尺寸，但不能单独证明孔径、壁厚或内部结构正确。

## 6. 作业任务

### 6.1 接入与建模

- 配置 GLM-5.3-Flash 模型服务，启动 OpenCode 与 SCA 编辑器。
- 观察 Agent 加载 Skill、读取文档和调用工具的过程。
- 从自然语言需求生成参数化零件，检查结果并导出 STEP。
- 提出一次参数修改，确认其他尺寸和结构保持不变。

### 6.2 建议建模案例

| 案例 | 初始需求 | 后续修改 | 观察重点 |
| --- | --- | --- | --- |
| 四孔安装板 | 80 × 50 × 5 mm，四个 Ø6 mm 通孔，孔中心距相邻边各 10 mm | 厚度改为 8 mm | 孔径、孔位和板长宽保持不变 |
| 开口圆筒 | 外径 40 mm，高 30 mm，壁厚 3 mm，底厚 4 mm，上端开口 | 壁厚改为 4 mm | 内径改变，外径、高度和底厚不变 |
| L 形支架 | 等宽 30 mm，水平长 50 mm，高 40 mm，统一厚度 5 mm | 高度改为 50 mm | 连接关系、宽度和厚度保持不变 |

案例用于观察不同结构的建模过程，不限制 Agent 只能处理这些形状。

### 6.3 需求澄清与反馈修正

分别观察参数缺失和执行失败时的处理方式：缺少关键条件时应提问；工具返回错误时应读取反馈、定位原因并修改代码。不能通过改变用户要求或放宽检查条件来掩盖失败。

## 7. 模型查看与导出

在 SCA 编辑器中查看整体外形、孔、开口及局部特征，结合几何测量判断是否满足需求。截图只能辅助观察，不能替代尺寸检查。

参数化 Python notebook 保留参数和建模步骤；STEP 用于交换几何结果；`.scadpkg` 保存 SCA 产品数据。按任务要求导出，并检查文件能够重新读取。使用保存的 notebook 重建时，应得到满足相同需求的模型。

## 8. 结果检查与问题分析

记录各项尺寸的目标值、实测值、容差及结论。除外形尺寸外，还应关注孔数、孔径、壁厚、贯穿性、连通性和实体有效性。

遇到失败时，区分需求歧义、接口使用错误、几何构造错误和模型服务问题。记录一次具体反馈及其后的修正操作，说明为什么修改有效。若未完成任务，应如实说明失败位置和已有结果。

## 9. 实验报告与提交内容

实验报告包括：

1. 环境、模型及依赖版本。
2. OpenCode、Skill 和 SCA 的分工与接入方式。
3. 需求输入、澄清、工具调用和反馈修正过程。
4. 修改前后模型截图及实际几何测量。
5. 失败原因、能力限制和改进方向。
6. 自行完成的内容及外部资料引用。

也可以补充展示其他模型在相同任务上达到的效果，并进行对比说明；保留 GLM-5.3-Flash 的结果，比较建模成功率、尺寸误差、运行时间与修复次数，注明模型版本及配置。

提交源代码、依赖配置、安装指南、参数化模型、STEP 文件和课程演示材料。不要提交 API 密钥、虚拟环境或下载缓存。

## 10. 可选扩展

OpenCode 仅作为 harness 演示。可换用 Pi、Claude Agent SDK 或其它支持多轮工具调用的框架，让 Agent 加载官方 Skill 并操作相同的 notebook。Skill 的安装目标可通过 `uv run sca skill targets` 查看；认证、工具权限和会话操作按对应框架配置。

其它扩展包括复杂特征建模、局部尺寸检查、参考图片输入及多零件装配。扩展应说明所增加的能力及其检查方法。

## 11. 常见问题

| 现象 | 检查方向 |
| --- | --- |
| 无法启动 SCA | 检查 Python 环境、依赖和系统运行库 |
| 模型接口认证失败 | 核对 `.env` 的端点、模型名和密钥 |
| Agent 找不到 Skill | 执行安装命令，核对 `skills/simplecadapi/SKILL.md` |
| 编辑器没有模型 | 在 Workspace 中打开实际 notebook，并查看执行日志 |
| 修改后结果不符 | 核对参数依赖、代码改动和实际测量 |
| STEP 无法打开 | 检查导出反馈、文件路径及导出对象 |
